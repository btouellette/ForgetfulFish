# Product Surface Phase PS2 — Game result surfacing

Status: planned

**Reachability gap this phase closes**: a game can already end inside the engine — `hasLost` is set by
`packages/game-engine/src/engine/sba.ts` (empty library, zero life) and by `CONCEDE` handling in
`engine/processCommand.ts` — but nothing outside the engine can observe it. `playerGameViewSchema` has no
result field, no message reports it, the Prisma `Game` model has no status/winner/ended-at column, and the
web shell has no terminal state. Today a player who concedes sees the UI simply stop responding to
commands, and the winner sees nothing at all.

**Depends**: `P6.8` (engine exposes a game result on the projected view). Everything below consumes that
field; none of it re-derives the result from `hasLost`.

**Open decision blocking `PS2.4`**: does a finished room support a rematch, or is it closed? This also
settles the long-idle room-expiry item in `TODO.md` and belongs in `docs/decisions/decision-log.md` before
`PS2.4` starts.

## Exit Criteria

- A game ending by concession, zero life, or an empty library is visible to both players.
- The result is durable across reconnect and server restart.
- The rematch-or-close policy is recorded as a decision.
